CSR (Client Side Rendering)

In CSR, the browser receives minimal HTML and downloads JavaScript. React runs in the browser, creates the UI, fetches data (usually with useEffect), and updates the page dynamically.

Flow-
    Browser requests page
    ↓
    Server sends JS files + empty/root HTML
    ↓
    Browser downloads JS
    ↓
    React renders UI in browser
    ↓
    API calls happen
    ↓
    UI updates

Characteristics
    Rendering happens in browser
    Uses useEffect for API calls
    Slower initial load
    Weaker SEO
    Hydration not needed
    Good for highly interactive apps   



SSR (Server Side Rendering)

In SSR, React components run on the server first. The server fetches data, generates HTML, and sends ready-made UI to the browser. Browser later hydrates client components for interactivity.

Flow-
    Browser requests page
    ↓
    Server fetches data
    ↓
    Server renders React to HTML
    ↓
    Browser receives ready UI
    ↓
    Browser downloads JS
    ↓
    Hydration happens

Characteristics
    Rendering happens on server
    Faster first page load
    Better SEO
    Initial HTML already available
    Hydration required for client components
    Good for SEO pages and fast initial rendering   


Hydration
    Hydration means React attaches interactivity (events, state, effects) to HTML already generated by the server.     

Note-
    “If a client component is used inside a server component, it can still be rendered on the server for initial HTML, but hydration happens only in the browser.”  


    lets say a button component(use client) is being used in the server component then the button component will be rendered on the server and hydration will happen in the browser.


SSG (Static Site Generation)

SSG means HTML is generated at build time and stored as static files. Users later receive already prepared HTML instead of rendering the page on every request.

Flow-
    npm run build
    ↓
    Next.js fetches data
    ↓
    HTML generated once
    ↓
    Static HTML files saved
    ↓
    User requests page
    ↓
    Ready HTML served instantly

Characteristics
    HTML generated once during build
    Very fast performance
    Excellent SEO
    Low server load
    Best for static content    

Good Use Cases
    blogs
    documentation
    portfolio websites
    landing pages
    marketing pages

App Router Behavior

In Next.js App Router:

Static generation is the default whenever possible.

Example:
const data = await fetch(url);

Usually becomes SSG because fetch is cacheable by default.
To Force SSR
fetch(url, {
  cache: "no-store"
});

This disables static generation and renders page on every request.

Static Page Example
export default function About() {
  return <h1>About Us</h1>;
}

This becomes static automatically because content does not change per request.

Hydration In SSG

If page contains client components: ("use client")

browser later hydrates them to enable:

    useState
    useEffect
    event handlers

Important Understanding    
    SSG - Generate once at build time
    SSR - Generate on every request


One-Line Interview Answer

SSG generates HTML at build time and serves pre-rendered static pages to users, making applications very fast and SEO-friendly. In Next.js App Router, pages are statically generated by default whenever possible.


ISR (Incremental Static Regeneration)
SSG + automatic background updating.
Build once
Update static page periodically

Example- 
    export const revalidate = 60;

    export default async function BlogPage() {
    const res = await fetch("https://api.com/blogs");

    const blogs = await res.json();

    return (
        <div>
        {blogs.map(blog => (
            <p key={blog.id}>{blog.title}</p>
        ))}
        </div>
    );
    }

What Does revalidate = 60 Mean?
- Re-generate page after every 60 seconds
